# Releasing Raft

The version lives in one place, `[workspace.package]` in `Cargo.toml`
(`packaging/version.sh` prints it, `packaging/version.sh set X.Y.Z` changes it).

## How a release happens

1. Every push runs **CI** (`.github/workflows/ci.yml`: `cargo xtask ci` and the script tests).
2. When CI passes on `main`, **Release** (`.github/workflows/release.yml`) reads the version.
   If `vX.Y.Z` has no published release yet, it builds the packages and publishes the release
   (a draft first, then published once every file is uploaded). If it has one, nothing is
   built: a published release is never overwritten, a fix is a new version.
3. A version with a suffix (`0.2.0-rc.1`) is published as a pre-release.
4. Run by hand (Actions → Release → Run workflow), Release only builds the packages and keeps
   them as the run's artifacts, on any branch.

## Steps

1. Add the version's section to `CHANGELOG.md`: `## [X.Y.Z] — YYYY-MM-DD` with *Added* /
   *Changed* / *Fixed*, and the link line at the end. The release notes are this section, and
   Release fails before building anything when it is missing.
2. `packaging/version.sh set X.Y.Z`, then `cargo xtask ci`.
3. Commit `Cargo.toml`, `Cargo.lock` and `CHANGELOG.md` together and push to `main`.
4. **The date** in the changelog is the commit date of that version commit (the one the tag
   points to), in local time — not the day the release appears. If commits are backdated,
   write it afterwards, from
   `git log -1 --format=%cd --date=format-local:%Y-%m-%d <commit>`.
5. **The version commit must not touch `.github/workflows/`**: the workflow's token may not
   create a tag on a commit that changes workflows (HTTP 403). Workflow changes go in an
   earlier commit.

## Packages

`packaging/linux.sh` and `packaging/appimage.sh` (after `cargo build --release -p raft` and
`packaging/licences.sh`):

| File | What |
|---|---|
| `raft-X.Y.Z-linux-x86_64.tar.gz` | `raft`, `build-catalog`, `rename-books`, desktop entry, icon, licences |
| `raft_X.Y.Z_amd64.deb` | the same, installed in `/usr` (Ubuntu 22.04+, Debian 12+) |
| `raft-X.Y.Z-1.x86_64.rpm` | the same, for Fedora / RHEL / openSUSE (`rpmbuild`; package `rpm` on Ubuntu, `rpm-build` on Fedora); dependencies named by hand (`AutoReqProv: no`) |
| `raft-X.Y.Z-x86_64.AppImage` | the same in one file (appimagetool 1.9.1 and type2-runtime 20251108, pinned by sha256 in `appimage.sh`, cached in `target/appimage-tools/`) |
| `SHA256SUMS.txt` | checksums (made by the workflow) |

Built on Ubuntu 22.04 (glibc 2.35). `packaging/check.sh dist` opens each package (tar.gz,
.deb, .rpm, AppImage) and fails when a file is missing; the workflow also fails when one of the
four was not built. A missing `dpkg-deb` or `rpmbuild` only skips that package locally.

## Licences

Every package carries `LICENSE-MIT`, `LICENSE-APACHE`, `NOTICE` and `THIRD-PARTY.txt`
(`copy_docs` in `packaging/env.sh`). `THIRD-PARTY.txt` is generated by `packaging/licences.sh`
with cargo-about (the version is in `packaging/env.sh` and in `release.yml`), from
`about.toml` and `packaging/about.hbs`; it fails on a crate with a licence not in `accepted`,
and when egui's font licences are missing. A new egui version changes the checksums of the
font licence files in `about.toml`: take them again with `sha256sum fonts/*.txt` in the
`epaint_default_fonts` crate.
